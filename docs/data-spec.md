# 데이터 수집 명세와 연구 윤리 (로드맵 3단계)

정한 날: 2026-11-27 (사용자 결정). 이 문서는 Firebase 연결(로드맵 4단계)의 저장 구조와 보안 규칙, 그리고 IRB 서류(연구계획서의 자료 수집·보관 항목, 연구 설명문·동의서)의 기준입니다.
앱의 화면 프로토타입(시연 로그인, 브라우저 저장)이 이 명세대로 동작하며, 서버를 연결할 때는 `src/state/`의 저장 함수만 바꿉니다.

`확인 필요`로 표시한 항목은 학교·IRB·법령으로 확인한 뒤 확정합니다.

---

## 1. 계정과 역할

### 1.1 로그인과 가입

| 단계 | 내용 |
| --- | --- |
| 로그인 | 구글 계정(Firebase Auth의 Google 제공자). 학생이 비밀번호를 만들거나 잊을 일이 없고, 관리자가 비밀번호를 초기화할 일이 없습니다. |
| 처음 한 번 정보 입력 | 학생: 학년도, 학번(예: 10203 = 1학년 2반 3번), 이름 / 일반인: 이름, 소속, 가입 이유 |
| 승인 | 관리자가 올린 **학생 명단**(학년도·학번·이름)과 같으면 바로 승인됩니다. 명단에 없는 학생과 일반인은 관리자가 승인합니다(하나씩 또는 모두). 명단을 나중에 올려도 기다리던 학생 중 맞는 학생은 승인됩니다. |
| 거절 | 관리자가 거절하면 "승인되지 않았어요" 안내가 나옵니다. |

- 프로토타입: 구글 대신 이메일을 입력해 로그인을 흉내 내고, 처음 로그인한 계정이 관리자가 됩니다(`#/account`).
- `확인 필요`: 학교가 나눠 준 구글 워크스페이스 계정은 학교 관리자가 외부 앱 로그인을 막아 둘 수 있습니다. 시범 운영 전에 학교 계정으로 로그인이 되는지 확인합니다. 막혀 있으면 학교 관리자에게 이 앱을 허용해 달라고 요청하거나 개인 구글 계정을 씁니다.

### 1.2 역할과 할 수 있는 일

| 역할 | 할 수 있는 일 |
| --- | --- |
| 관리자 | 가입 승인·거절, 학생 명단, 역할 바꾸기, 연결표(보기·내려받기·지우기), 연구 윤리 설정, 그리고 교사의 모든 일. 관리자는 한 명 이상 있어야 합니다. |
| 교사 | 학급·세션(회차)·세션 코드, 수업 설정, 채점·대화 태그·분석·면담·녹음, 설문 편집 |
| 학생 | 승인되면 증명 연습. 교사가 준 **세션 코드**를 입력한 세션에서 AI와 탐구하기 |
| 일반인 | 승인되면 증명 연습. 세션 코드를 받으면 AI와 탐구하기도 할 수 있으나, 탐구 기록은 연구 분석에서 기본으로 빠집니다. |

### 1.3 세션 코드

- 세션(학급 × 회차)마다 6자리 코드가 생깁니다. 헷갈리는 글자(0, O, 1, I)는 쓰지 않고, 화면에는 `K7P-4QX`처럼 보입니다. 학생은 대소문자·하이픈·띄어쓰기와 관계없이 입력하면 됩니다.
- 학생은 회차가 바뀌면 새 코드를 입력해 여러 세션에 들어갈 수 있습니다.
- 교사는 코드를 닫거나(새로 들어올 수 없음, 이미 들어온 학생은 계속) 다시 만들 수 있고, 들어온 사람 수를 봅니다.
- 서버 규칙: 학생은 자기가 들어간 세션의 문서만 읽고, 그 세션의 자기 기록만 씁니다.

## 2. 가명 처리와 연결표

- 모든 사용자는 가입할 때 **연구 번호**(예: `R-7K3Q`, 무작위, 겹치지 않음)를 받습니다. 연구 기록·채점·분석·CSV에는 연구 번호만 씁니다.
- **연결표**(연구 번호 ↔ 이름·학번·소속·이메일)는 서버에 두고 **관리자만** 읽습니다(사용자 결정). 교사 화면의 학생 목록에는 연구 번호가 보입니다.
- 관리자는 연결표를 CSV로 내려받고, 한 명씩 또는 모두 **연결 지우기**를 할 수 있습니다. 연결을 지우면 이름·학번·소속·이메일이 지워지고 연구 번호와 기록은 남아 가명 자료가 됩니다.
- 학생 보호자의 연구 동의(종이)는 관리자가 연결표에 받은 날짜를 적습니다.
- 면담처럼 실제 학생을 불러야 할 때는 관리자가 연결표로 찾습니다.
- 서버 구조: 사용자 문서 `users/{uid}`(역할·상태·연구 번호·참여 세션)와 연결 문서 `links/{uid}`(이름·학번·소속·이메일·보호자 동의)를 나누고, `links`는 관리자만 읽고 씁니다. 로그인 이메일 자체는 Firebase Auth에 남으므로, 연구가 끝나면 학생 계정을 지우는 절차도 둡니다(6절).

## 4. 동의

| 동의 | 방식 | 기록 |
| --- | --- | --- |
| 학생 연구 동의 | 탐구 홈의 "연구 참여 동의" 화면(동의서 판 관리) | 동의 여부, 판, 시각, 바꾼 기록 |
| 보호자 연구 동의 | 종이 동의서 → 관리자가 연결표에 날짜 | 날짜 |
| 면담·녹음 동의(학생·보호자·녹음) | 종이 → 교사가 면담 화면에 날짜. 학생·보호자 동의 전에는 면담 "완료" 불가, 셋 다 있어야 녹음 | 날짜 |

**철회(사용자 결정: 철회 전 자료는 사용)**: 학생이 동의했다가 철회하면 상태가 "철회함"이 되고, 철회 시각 **전에 제출한** 단계·설문·원리 활동만 연구 분석에 남습니다. 그 뒤의 자료는 수집해도 분석에서 빠집니다(`services/surveyAnalysis.js` `forResearch`). 동의서에도 이 내용을 적습니다. 처음부터 동의하지 않은 학생은 분석에서 빠지고(교사가 따로 넣을 수는 있음), 수업 활동은 똑같이 합니다.

## 5. IRB 심의를 받을 때와 받지 않을 때 (관리자 화면 "연구 윤리 설정")

사용자 결정: 아직 계획은 없으나, 받게 되면 설정 하나로 바뀌도록 둡니다.

| 항목 | IRB 받음 | IRB 받지 않음 (학교 안 수업 개선 연구) |
| --- | --- | --- |
| 학생 동의서 양식 | 연구 설명문 + 동의서: 연구 제목, 목적, 참여 방법·기간, 수집 자료, 위험과 이익, 자발적 참여와 철회, 개인정보 보호·보관, 문의(연구책임자, IRB 승인번호·연락처) | 학교 승인 안내, 수집 자료, 가명 처리, 불이익 없음, 철회, 보호자 안내 |
| 입력하는 연구 정보 | 연구 제목, 연구책임자·연락처, **IRB 승인번호, IRB 연락처** | 연구 제목, 연구 담당·연락처 |
| 연구 자료 보존 | 연구 종료일 + **3년**(바꿀 수 있음) 뒤 파기. `확인 필요`: 3년은 생명윤리법 시행규칙의 연구 기록 보관 기간을 참고한 값이므로, 심의받은 연구계획서의 기간을 따릅니다. | 관리자가 정한 삭제일 |
| 계정 화면 | IRB 승인번호 안내 | – |
| 같은 점 | 학생 연구 동의, 보호자 동의 확인, 가명 처리(연구 번호), 연결표는 관리자만, 철회 전 자료 사용, 면담·녹음 별도 동의 | |

- 양식은 "연구 윤리 설정"에서 넣고, "설문과 연구 동의"에서 고칠 수 있습니다. 넣을 때마다 동의서 판이 바뀌어 학생이 어느 판에 동의했는지 남습니다.
- IRB 제출용 서류는 기관 양식에 맞춰야 합니다. 앱의 양식은 학생 화면에 보이는 요약입니다.

## 6. 보존과 삭제

| 자료 | 보존 | 삭제 방법 |
| --- | --- | --- |
| 연구 자료(가명) | 5절의 삭제 예정일까지 | 관리자가 삭제(서버 연결 뒤 "연구 자료 모두 지우기"와 삭제 기록) |
| 연결표 | 연구 기간(면담·동의 확인이 끝날 때까지) | 관리자가 "연결 정보 모두 지우기"(먼저 CSV 내려받기 권장) |
| 면담 녹음 | 연구 기간(녹음 관리의 보관 기한) | 기한 14일 전부터 알림, 교사가 내려받은 뒤 직접 삭제(자동 삭제 없음) |
| 계정(이메일) | 연구 기간 | 연구가 끝나면 학생·일반인 계정을 지움(서버 연결 뒤 관리자 기능) |
| 증명 연습 기록 | 학생이 쓰는 동안 | 학생·보호자가 요청하면 삭제. `확인 필요`: 학년이 바뀔 때 지울지(제안) |

**삭제 요청**: 학생·보호자가 삭제를 요청하면 관리자가 연결표로 찾아 그 학생의 연결 정보와 연습 기록을 지웁니다. 연구 자료는 철회 원칙(철회 전 자료 사용)을 따르고, 이미 발표한 집단 통계는 되돌릴 수 없다고 동의서에 적습니다. `확인 필요`: 요청 처리 기한과 기록 방법.

## 7. 내려받기

- 형식: CSV(Excel용 UTF-8 BOM). 연구 분석·설문·면담 기록 CSV는 연구 번호만 씁니다.
- 연결표 CSV는 관리자만 내려받습니다.
- 서버 연결 뒤 내려받기는 서버에서 권한을 확인한 뒤에만 만듭니다.

## 8. AI 점수의 용도 (사용자 결정)

- 연습 모드의 AI 점수: 학생 자기 점검용입니다.
- 연구 분석의 점수: 기본은 교사 채점입니다. AI 채점 제안은 참고로 남기고, AI가 채점자의 판단을 바꾸었는지 분석하는 데 씁니다(`aiSeen`, `criteriaBeforeAi`).
- **"AI를 보조 채점자로 쓰기"(채점 화면 설정, 기본 꺼짐)**: 켜면 점수 출처에 "채점자 1과 AI 평균"이 생기고, 채점자 ↔ AI 일치도(합계 정확 일치율, 평균 차이, 기준별 카파 평균)가 나옵니다. 끄면 참고로만 남습니다.

## 9. 정답 데이터

- 연습 모드의 정답(빈칸 정답, 예시 증명)은 지금처럼 앱 안에 둡니다(학습용, 빠르고 오프라인에서도 됨). 다만 인증(배지)은 서버가 다시 확인합니다.
- 연구 모드는 교사 채점이라 정답 노출 문제가 없습니다.

## 10. 서버 구조 (로드맵 4단계, 4-1에서 계정 부분 확정)

4-1에서 확정한 것(2026-11-27, `api/account.js`, `firestore.rules`)
- `users/{uid}` = { role, status(profile/pending/approved/rejected), kind(student/guest), researchId, sessionIds, createdAt, submittedAt, approvedAt, approvedBy, autoApproved, unlinkedAt }. 실명 없음. 본인과 교사·관리자가 읽음.
- `links/{uid}` = { email, profile(학년도·학번·이름 또는 이름·소속·가입 이유), guardianConsent }. 관리자와 본인만 읽음.
- `roster/{학년도-학번}` = { year, studentNo, name, addedAt }. 관리자만 읽음.
- `researchIds/{연구 번호}` = { uid }. 연구 번호가 겹치지 않게 서버가 만듦(아무도 읽지 않음).

- `classes/{classId}` = { name, teacherUids, practice, createdAt, createdBy }. 담당 교사(teacherUids)와 관리자만 읽음. 서버만 씀.
